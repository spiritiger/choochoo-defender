## ⭐ 「三个量」口径（v0.6.18 定案，别再混）
**步数** = `GS.railPath.length` = 导出 `rail(N)` 的 N（含重复格）· **格数** = 去重格数 · **十字** = 被走 ≥2 次的格（度数 4）。
**恒等：步数 ≥ 格数；步数 − 格数 = 十字数。** 报 bug / 写断言**指名是哪个量**。

## 铁轨求解链（`GS.recomputeRails`）
`floodU → thinNeck → keepCoreComponent → pruneU → normalize(洞F) → boundaryOf(∂U) → helpersOf(H) → closedTrail → enclosesCore`
- 本质 = 一条围住镇中心的**闭合迹（欧拉回路）**；口径 = 优先覆盖最多轮廓格，无解才放弃。
- **五上限**：`XMAX=6`(十字) / `HMAX_CAP=16`(补格) / `TOL_MAX=6` / `RANK_CAP=19` / `START_TRIES=9`；另 `SPUR_XMAX=8`。
- **主解两阶段**：①定档（`si=0` 爬补格阶梯 → 最小有解档 `k*`）→ ②择优（`k*` 档前 9 起点，三级字典序 覆盖↑→十字↓→格数↓）。
  ⚠️ **顺序不可颠倒**（失败证明是指数阶）；补格数**不在**字典序里。
- **四级兜底**（各级独立 `freshBudget`）：①容差阶梯 → ②快速兜底 → ③圈空间枚举 `bestRingExact`（与 DFS 双路择优）→ ④剥层 `peelOnce`。
- **⑤ `spurSolver`**：每边 ≤2 次、第 2 次必反向；循环层级**顺序不可换**（起点外 → 十字中 xcap 递升 → 容差内 → 每档两遍常规/flip）。
- ⭐ **大王澄清（2026-09-28，需求口径别再说错）**："第 2 次必反向"是**走线层**描述，**不是**"允许同一条铁轨往返"的许可。
  需求口径 = **同一格允许出现两条铁轨，且仅限十字或分岔（T 岔）**；双走边只许当**支线咽喉**（桥边"进桥绕一圈原路出桥"），
  v0.8.2 桥边约束（双走边必须是割边）正是这道闸。贴片对账（renderer.js:130-148）：度 4=十字、度 3=T 岔
  （"主环 2 边 + 桥边往返 2 次，同一条边只占 1 个方向"）、度 1=折返端头（尽头车挡，仅"起点即半岛"退化走线）、
  往返桥边贴片与普通双线段完全一致。**别把 mm=2 说成"允许反向重走"** —— 正确说法 = "把⑤已有的分岔/支线形状家族给主解"。
- ⭐ **需求表述定稿（2026-09-28 程序重放锤定，按"格"说别按"边"说）**：列车走线 = 闭合路线、全程朝前、
  **每格最多经过 2 次**；第 2 次经过仅两种 —— ① **十字**（4 条边各 1 次，两条独立轨）② **分岔**（桥边折返，
  桥边必须是割边）。禁端头、禁辫子。"每边 ≤2 次、第 2 次反向"只描述分岔那一半，不当总规则。
  ⚠️ **口径坑**：测试术语"十字"（=被走 ≥2 次的格 = 步数−格数）≠ 渲染"十字贴片"（度 4）——
  重走格若**折返同边**→T 岔（度 3），**走新边**→十字（度 4）。实锤盘 2026-09-28 12:26 导出：
  rail(18)=16 格，(5,8)(6,8) 均 visit=2/deg=3 → 两个 T 岔，重走边 (5,8)-(6,8) 程序验证是割边，⑤ 合法产物。
- **预算**：主解节点 150 万 + 墙钟**阶梯 700ms**（贴近最差自然 ~485ms，**别再往下调**）/ 快速 150 / 枚举+剥层 250；
  ⑤ `SPUR_BUDGET_MS=150`（节点放大到 150万×40，墙钟是硬闸）。

## ⭐ 真实瓶颈（2026-09-28 实测定案，做重构前必读）
- **主矛盾 = 主解缺「往返」自由度**：四处 `closedTrail` 调用**都传 `mm=1`**，`mm=2` 只存在于后置的 ⑤；
  ⑤ 平均补 **5.17 格**轮廓（最大 11）—— 是成段大缺口，不是小缝。
- 一行改动（`mm` 1→2）实测（298 轮）：

  | | 满覆盖 | 覆盖 | 十字 | ⑤命中 | 真失败 | 中位 | P90 |
  |---|---|---|---|---|---|---|---|
  | 现状 mm=1 | 75.8% | 90.7% | 2.16 | 50% | 23.8% | 166ms | 1004ms |
  | **主解 mm=2** | **93.6%** | **98.5%** | 2.58 | **1%** | **6.4%** | **19ms** | **364ms** |

  逐盘 提高 66 / 变差 1 / 持平 231；45 黄金盘全绿（含硬断言 [13]十字=2、[15]十字=0）。
- **已证伪（别再试）**：扩搜索空间（补格 1→2/3 圈，HMAX 16→32/48）满覆盖 → **70.0%/69.3%**，耗时 +36%；
  加预算（节点 ×13 + 主墙钟 ×4.3 + 支线 ×8）满覆盖仅 **+6.4pp**、耗时 ×3.8（max 4.3s）。
- ⇒ **瓶颈是自由度，不是搜索能力。** min-cut / T-join 那类多项式精确算法**不推荐**：目标函数不匹配
  （min-cut 最小化"用非轮廓格数"）、割集未必是连通曲线（长条 U 切两刀）、瓶颈实测不在此。
- ⚠️ **真时钟下结果确定**（同盘复跑 140 轮走线 0 差异）。

## 🔬 方法论（详见技能 `ab-experiment-prove-refactor-safe`）
1. 采样只能证"存在"，**穷举才能证"不存在"**；做 A/B **先掐掉旁路**；**必加"去约束"对照组**。
2. **性能对照必须自造固定种子盘** —— ⚠️ 连产品 `GS.newGame()` 都不能用（内部 `Math.random()` 撒金币 ⇒ 不同配置消耗随机数
   次数不同 ⇒ **地形从第 0 轮就分叉**，实测指纹 24/24 全不同）⇒ **自建确定性开局**。🔎 记一个**与求解结果无关的地形指纹**逐轮比对。
3. ⭐ **必须报"被测分支的覆盖率"**（曾 1411 盘只有 32 盘走到被改分支）。
4. ⚠️ **探针字段会读到上一轮残留值**（提前 return 的路径不写 `debugXxx`）⇒ 每样本前 `= null`；
   **兜底自检 = 两个互补统计必须相加 100%**。
5. ⚠️ **大批量 A/B 用真时钟**（有界）；关墙钟只测"能力上限"且样本要小（曾白等 15 分钟）；脚本边跑边 print。
6. ⚠️ 别用单字母 `L` 同时当日志函数和环长（静默无日志）。
7. 📌 **"测试抄了一份实现"比没有测试更坏**（假绿灯）；**同一判据在两条路径上，最危险的是"改了 A 忘了 B"**。

### 📌 零行为变更验证套路（照抄）
对照版来源：① 小改动 → 从单文件产物抽旧源码；② 产物也改了 → 复制新文件手工还原；③ 大改动 → 逆向文本替换。
**自检**：新符号只在新版、旧符号只在对照版（否则是"自己跟自己 diff"）。**双沙箱**（`vm.runInContext`）× 固定种子盘，
比对外露产物（`railPath/railSet/railInner/railRect/goldInRegion` + `countTurns` + 渲染指令序列）。
⚠️ 别用 `debugNoDeadline=true` 跑大样本（spur 6000 万节点被病态盘烧穿，20 盘就卡死）→ **用假时钟**（`Date.now()` 每次固定跳 4ms）。

## 环境坑（本机）
- **Bash 可用** → 首选 Read/Grep/Glob/Write/Bash；`cmd /c` 被安全策略拦。PowerShell 偶报
  `sandbox-center cmd decisionRecord missing actual resource subject` → 换 Bash 重试。
- ⚠️ **PS stdout 会被吞**（exit 0 无输出）⇒ node 脚本自己 `fs.writeFileSync(log,'utf8')` 再 Read；**别用 PS 重定向**（写成 UTF-16）。
  PS `Remove-Item` 对 `%TEMP%` 批量删除会静默吞。
- ⚠️ `Set-Content -Encoding UTF8` **会加 BOM** → 用 `[System.IO.File]::WriteAllText($f,$t,(New-Object Text.UTF8Encoding($false)))`。
- ⚠️ **`index.html` 是 CRLF**（替换脚本先探测 EOL）；**正则匹配 HTML 标签别假设属性顺序**（写死会静默漏内联）。
- node 脚本挂 `process.on('uncaughtException')` 兜底写日志。
