## ⭐ 铁轨「三个量」口径（v0.6.18 定案，别再混）
- **步数** = `GS.railPath.length` = 导出 `rail(N)` 的 N（**含**重复经过的格）
- **格数** = **去重后**的格数；**十字** = 被走 **≥2 次**的格（度数 4）

**恒等：步数 ≥ 格数；步数 − 格数 = 十字数**。报 bug / 写断言**指名是哪个量**（曾混过一轮，大王对、我错）。

## 铁轨求解链（`GS.recomputeRails`）
`floodU → thinNeck → keepCoreComponent → pruneU → normalize(洞F) → boundaryOf(∂U) → helpersOf(H) → closedTrail → enclosesCore`
- **本质**：一条围住镇中心的**闭合迹（欧拉回路）**；覆盖口径 = 优先覆盖最多轮廓格，无解才放弃（`TOL_MAX=6`）。
- **五个上限**：`XMAX=6`(十字) / `HMAX_CAP=16`(补格) / `TOL_MAX=6` / `RANK_CAP=19` / `START_TRIES=9`；`SPUR_XMAX=8`。
- **主解两阶段（v0.6.19）**：① **定档**（`si=0` 跑补格递升阶梯 → 最小有解档 `k*`）
  → ② **择优**（`k*` 档跑前 9 起点，**三级字典序**：覆盖↑ → 十字↓ → 格数↓，十字 0 早停）。
  ⚠️ **顺序不可颠倒**（补格阶梯的"失败证明"是**指数阶** ~2.5×/档，每起点各爬一遍必爆预算）。
  ⚠️ **补格数不在字典序里** —— `ki` 阶梯只是启发式。
- **四级兜底**（各级**独立** `freshBudget`，不连坐）：① 容差阶梯 → ② 快速兜底（`desc` 补格从大到小）
  → ③ 圈空间枚举 `bestRingExact`（v0.6.17 起**并列主求解器**，与 DFS 双路择优）→ ④ 剥层 `peelOnce`。
- **⑤ 往返支线 `spurSolver`（v0.8.0 建，v0.9.0 大修）**：每边 ≤2 次、第 2 次必反向（乘子图欧拉回路，
  列车全程朝前不倒车），收编**单条桥边挂的 2 格宽半岛**（1 格宽脖子仍被 `thinNeck` 截肢、救不了）。
  - v0.9 循环层级（**顺序不可换**）：**起点外**（全量 `Bl`）→ **十字中**（`xcap` 2→`SPUR_XMAX` 递升）
    → **容差内**（`t` 0→`tolTop`）→ 每档**两遍**（常规 + flip 拐弯优先）。
  - ⚠️ **铁闸 `if (st.cov <= cov0) continue;` 不可拆** —— 拆了低覆盖脏解会顶掉主解（331 盘 22 盘覆盖回归，s241 cov32→3）。
  - 容差卡死 `tolTop = |Bl| − cov0 − 1` ⇒ 命中必**严格**更优；主解已盖满轮廓时直接 `return null`（零开销）。
  - 预算：`freshBudget(SPUR_BUDGET_MS=150)` + 调用点把节点放大到 `150万 × 40`；墙钟是硬闸。
- **桥边约束（v0.8.2）**：重数 2 的边必须是搜索图**割边**（Tarjan 预判，仅 `mm=2` 算）——
  非桥边双走不产生新覆盖只织辫子（10:42 盘：44步/7十字 → 36步/2十字）。
  ⚠️ 预计算块里别引用"后面才赋值的 var"（var 提升 = undefined，桥边表全零，A/B 抓回）。
- **渲染贴片（v0.8.1）**：T 岔支臂用**弯道同款切向弧（喇叭口）**并入贯通轴；两形态
  A「环拐进支臂」（对角 pass）、B「环直穿+支臂折返」（零向量 pass + prevDir，气球形折返环）。
  ⚠️ **方向箭头 v0.8.3 已整体移除**（`__chevron_retired` 保留备恢复）；**pass 向量保留收集**（喇叭口依赖它）。
  ⚠️ `closedTrail` 的 `mm` 参数：=1 与旧版逐分支等价（A/B 证过），只有⑤用 2。
- **预算**：主解节点 **150 万** + 墙钟**阶梯 700ms**（v0.6.20 由 400 抬高）/ 快速 150 / 枚举+剥层 250。
  ⚠️ 700ms 已贴近最差自然耗时（~485ms），**别再往下调**。
  ⚠️ `closedTrail` 里 `budget.left = left;` 的**写回不能删**。
- ⚠️ **圈空间枚举铁律：圈向量必须做真异或** —— 写成"置 1 / 置 0"会退化成**并集** → 枚举出奇度子图 → 只能走出"路"而非"环"。
- **反缩水保险**：`finalRing` 沿用旧环的条件含**"对当前轮廓的覆盖格数 ≥ 新解"**（旧口径"环长不下降"是错的）。
- ⚠️ **几何铁律（别当 bug 修）**：单格脖子连接的半岛**永远围不进环**；`thinNeck` 截肢是正确行为。
- **「直行 vs 拐弯」是两处机制**：① 生成期直行优先（`closedTrail` 的 `dfs`，v0.6.16）
  ② 事后配对最优（`GS.straightenRing`，v0.6.10，枚举 3^K 配对）。
  ⚠️ **"零拐弯"与"大环"互斥**（实测零拐弯最长仅 36 格）；几何无解时两处都不生效 —— 别再想在算法上消除它。
- **`hLimit` 语义** = **"本轮最多允许用几个补格"的上界**（旧名 `kmax`）。
  ⚠️ v0.6.17 那条"判据写反"是我的**误判，已推翻**（上界全面更优；原"铁证"失效是因为双路择优盖住了 DFS 差异）。

## 🔬 方法论（多轮教训沉淀）
1. **采样只能证"存在"，穷举才能证"不存在"**。
2. **做 A/B 先掐掉旁路**（如枚举路）—— 旁路胜出会把主路行为完全盖住。
3. **必加"去约束"对照组**：某写法与"无约束"逐格差异 = 0 ⇒ 该约束根本没生效。
4. **证明重构/改名零行为变更**：逆向文本替换造对照版（**断言替换命中 > 0**）+ 大批量逐格 diff。
   💡 纯格式/缩进改动更省事：直接跟**改动前的产物文件** diff。
5. **性能对照必须自造固定种子盘** —— `test_rail [4]` 用 `Math.random()`，前后不是同一批盘（耗时不可比）。
6. **改完必须真跑**。7. ⚠️ **别用单字母 `L` 同时当日志函数和环长**（静默不产出日志）。
8. ⭐ **必须报"被测分支的覆盖率"**：光说"跑了 N 盘"不算数（曾 1411 盘里只有 32 盘走到被改分支）。

## 环境坑（本机）
- **Bash 本会话可用**（`dirname` 等齐全；历史上曾长期半残）→ 首选 Read/Grep/Glob/Write/Bash，`cmd /c` 被安全策略拦。
- **PowerShell 工具偶尔报 `sandbox-center cmd decisionRecord missing actual resource subject`** —— 换 Bash 或换单独命令重试。
- **PowerShell stdout 会被吞**（exit 0 但无输出）—— node 脚本必须自己 `fs.writeFileSync(log,'utf8')` 再 Read；
  **别用 PowerShell 重定向**（会写成 UTF-16）。**PS `Remove-Item` 对 `%TEMP%` 批量删除会静默吞**（清临时目录用 node/Bash 删）。
- ⚠️ **`Set-Content -Encoding UTF8` 会给文件加 BOM** —— PowerShell 改完源文件必须查头字节；
  用 `[System.IO.File]::WriteAllText($f,$t,(New-Object Text.UTF8Encoding($false)))`。
- ⚠️ **`index.html` 是 CRLF** —— 任何字符串替换脚本必须先探测 EOL。
  ⚠️ **正则匹配 HTML 标签别假设属性顺序** —— 写死会**静默漏内联**（打包成功但缺内容，极难发现）。
- node 脚本要挂 `process.on('uncaughtException')` 兜底写日志，否则抛错时日志压根不生成。

## 📌 零行为变更的验证套路（本项目已成型，直接照抄）
1. **对照版从哪来**：① 小改动 → 从**单文件产物**抽内联的旧源码；② 产物也改了 → 复制新文件**手工还原**（比写正则稳）；
   ③ 大改动 → 逆向文本替换。
2. **必做自检**：新符号只在新版、旧符号只在对照版，否则就是"自己跟自己 diff"的假通过。
3. **双沙箱**（`vm.runInContext` 装载器）×**固定种子盘**，比对外露产物
   （`railPath/railSet/railInner/railRect/goldInRegion` + `countTurns`，再加渲染指令序列）。
4. ⚠️ **别用 `debugNoDeadline=true` 跑大样本**：墙钟关了以后 spur 的 6000 万节点预算会被病态盘烧穿（实测 20 盘就卡死）。
   **替代手法 = 假时钟**：给沙箱一个 `Date.now()` 每次调用固定跳 4ms 的 `Date` —— 既确定性，又把预算边界压回真实量级（500 盘约 6 分钟）。
5. 盘型要**按"被改分支会不会走到"来设计**（"从镇中心向外长空地"的出环率 79%，随机盘只有 2%）。

## 与大王协作的约定
- 调性：**简洁利落**，结论先行；但要**带可核验的数据**，别给"应该没问题了"这类结论。
- **改行为前先翻规格**；规格与代码冲突时先分清"哪段是大王原话、哪段是实现者翻译"，后者可能收错。
- **不擅自改代码**：先给结论 + 让大王拍板（除非他说"直接做"）；**不擅自执行收尾动作**（打包/发布/部署/导出）。
- 解释机制要**通俗 + 配图**；交付用 `present_files` 让大王能直接看。
- **实测优先**：先量数据再下结论（多轮"我的猜测被数据推翻"）。
