## 0. 一句话需求

铁轨 = 在「玩家清出的可铺轨格」上自动求一条**单线闭合走线**（乘子图欧拉回路）：**围住镇中心，尽量盖满清空区外轮廓（含值得纳入的半岛），重走格尽量少，占用格尽量少**——在确定性预算内给出上述字典序意义下的最好解，且**任何情况下都至少有一条合法环**。

## 1. 术语与「三个量」口径（沿用 v0.6.18 / v1.0 / v1.6.7 定案）

讨论铁轨必须先指名是哪一个量，历史上因混用返过工：

| 量 | 定义 | 代码口径 | 玩家视角 |
|---|---|---|---|
| **步数** | `railPath` 序列长度（含重复经过的格；闭环回绕，也 = 边条数） | `ring.length` | 导出文本 `rail(N)` 的 N |
| **格数** | 去重后的格数 | `Object.keys(visitMap(ring)).length` | 铁轨占几个格子 |
| **重走格**（旧名"十字"） | 环上被走 ≥2 次的格数 | 计数 `vis[cell] >= 2` | 有几处交叉/分岔 |

恒等式：**步数 ≥ 格数；步数 − 格数 = 重走格数**。

- **度数 = 用到的不同口数，不是口次总数**（v1.6.7 澄清）。重走格的渲染形态：走新边 → **十字贴片**（度 4，双直行）；折返同一条桥边 → **T 岔贴片**（度 3，支线咽喉）。"一趟直行 + 一趟弯道"只有 3 个口，是度 3 T 岔不是十字。
- 求解器内部另有两个对照量：**覆盖数**（目标第一优先，基准集见 §3-O1）、**补格数 H**（`hLimit` 卡的上界，非玩家可见量，**不在择优字典序里**，v0.6.17 定案）。
- 求解的数学对象统一称为**乘子图解**：在可铺轨格图上取边重数 ∈ {1,2}（重数 2 = 双向各一趟）的连通全偶度多重子图，走一条欧拉回路。主环、十字、往返支线都是它的特例——这是 v2 的统一形式化（设计方向见附录 A-D2）。

## 2. 功能不变量（硬约束 H1–H8）

每条附**可执行判据**（`js/state.js` `ringOkFull` / `test_rail.js` `ringError` 同口径）。违反任一条 = 非法解，不允许出现在任何输出里（含兜底环、预览环、Worker 回传环）。

| # | 不变量 | 可执行判据 | 来源 |
|---|---|---|---|
| H1 | **单条闭合走线**：一条欧拉回路，不是若干条环的拼接 | 环序遍历恰回到起点，步数 = 序列长度 | 规格 §2 / ringOkFull |
| H2 | **逐边正交、首尾相接**：相邻两格曼哈顿距离恰为 1 | `abs(dc)+abs(dr)===1` 逐边 | 规则原文 / ringOkFull |
| H3 | **每格最多经过 2 次** | 逐格计数 ≤2 | 大王规则 5（v1.0 按格定稿） |
| H4 | **每条无向边最多走 2 次，且第 2 次必反向**（同向重走 = 倒车，非法） | 无向边计数 ≤2 + 方向对不重复 | 规则 5 / ringOkFull |
| H5 | **无端头**（度 1 尽头车挡禁止）。重走格的第 2 次经过仅两种合法形态：十字（度 4 双直行）、T 岔（度 3 桥边咽喉，双走边必须是割边） | 端头禁令（v1.0）；桥边约束（v0.8.2） | 档案 4.1 / 4.2 |
| H5b | **往返/掉头禁令**（大王 2026-10-11 对照页反馈拍板）：① 任何一次通行**同口进出**（进 W 出 W = 格内原地折返）非法；② 被走 2 次的格两趟合计口数 ≤2（W→E 去、E→W 回）非法。合并语义：**格层的"伸出去再原路退回"一律非法，唯一合法双走 = T 字岔穿越**。边界定稿（P6' 拍板）：**边层双走（两端皆 T 字岔）允许**——游戏内 T 字渲染为弧线，两趟各走各的弧，非视觉原路往返（k60 金币小圈即此形态，保留）。⇒ P1 半岛纳入的可行形态为"挂接边两端各 ≥3 口"（贴边死角）；单格脖子/一格宽通道数学上必然产生往返格，一律不收。v2 走线层（ringHasBacktrackCell）+ 区域层（挂接合法性前移，防不可覆盖格拖死容差阶梯——hard16 实锤）双重落实；v1 链路不受此禁令约束（legacy 冻结） | `ringHasBacktrackCell`（state.js）；test_rail_v2 V1c/V2 系用例 | 2026-10-11 对照页反馈 + P6' 裁决 |
| H6 | **围住镇中心**，且镇中心 **3×3 邻域整块**在环内（PROT 保护） | 边界洪水法 `enclosesCore`（不用射线法，自交处会误判） | 大王规则 2 |
| H7 | **只在可铺轨格上**（已清空 blank 且不压任何建筑）；环**内部**允许有废墟/建筑 | usable 位图 | 大王规则 4 |
| H8 | **走线呈现规则**：`railPath` 是有序序列，列车按格行驶；十字格能直行则直行（`straightenRing` 保证，只改配对不动边集，三个量零变化）；渲染按格画贴片，不需要方向逻辑 | `isStraightThrough` 唯一直行判据 | 规则配套约定 |

## 3. 质量目标（软目标 O1–O3，三级字典序，顺序不可颠倒）

对**同一盘面**的多个合法解，按字典序择优：

**O1 覆盖↑** —— 环上去重格 ∩ **覆盖基准集 B\*** 的格数越多越好。
**O2 重走格↓** —— 越少越好（含 T 岔）。
**O3 格数↓** —— 去重格数越少越好。

- **补格数不在字典序里**（v0.6.17 定案）：hLimit 阶梯只是"少用补格"的启发式手段。
- **不承诺数学最优**：最大面积/最大覆盖是 NP 级优化，程序只做"预算内的最好"（大王规则 1 原文如此）。预算是行为的一部分（见 R2），因此**预算配置本身就是 O1–O3 语义的组成部分**，不是纯性能参数。
- **旧"面积口径"文字废止**：规格 §2 配套约定里"并列时先比用掉已清空格更多、再比环更短"的自然语言表述，与 O1/O3 观察一致但措辞歧义，统一以本节可执行口径（`ringBetter` 三级字典序）为准。

### O1 的 v2 语义变更：覆盖基准集 B\* 的构成（对应档案 ⭐ 需求④）

**现行口径**：B\* = **削脖子后**清空区 U 的外轮廓（thinNeck 截肢 ⇒ 脖子半岛的轮廓格不在基准集里 ⇒ 解再好也"看不见"它们）。

**v2 口径**：B\* = **完整清空区**（未削脖子）的外轮廓，**含"值得纳入的半岛"的轮廓格**。半岛经脖子/桥边往返（重数 2）纳入覆盖。

- 实锤依据（09:12 盘，档案 ⭐）：右上 2×2 空白半岛 {(7,3),(8,3),(7,4),(8,4)} 经单格脖子 (7,2) 挂主体，局部闭合走线 **已程序验证合法**——"满覆盖 94%+"的承诺在该形态上 100% 失败，属正确性缺陷而非优化项。
- **"值得纳入"的判据已拍板（P1，2026-10-11）：终点块为块状空地（≥2 格的 2 维块，如 2×2）即纳入；终点块是一格宽长走廊（1 维链）仍不纳入。** 覆盖基准集 B\* 由此定稿。
- B\* 变更影响一族下游口径：反缩水保险的比较（R4）、trimDetours 的 mark、spur 的 cov0、A/B 报表。**A/B 报表保留双口径**（旧 B / 新 B\*）以便对照与回归判定。

## 4. 运营需求（工程约束 R1–R7）

| # | 需求 | 说明 |
|---|---|---|
| R1 | **确定性可复现** | 同盘面 + 同预算 ⇒ 逐格一致输出。节点预算为主约束，墙钟只是防卡死安全网；回归测试一律 `GS.debugNoDeadline` 关墙钟。任何引入随机性/机器相关时序的设计（如真墙钟早停、迭代深化）不允许作为输出路径 |
| R2 | **预算分级独立，预算即行为** | 各级兜底拿独立 `freshBudget`，上级烧穿不连坐下级（v0.6.5 定案，前科见档案 3.1）。任何预算数值变更 = 行为变更，必须走 §8 A/B + 拍板 |
| R3 | **anytime 保底：最差也必须有合法环**（v2 新增，升格自 09:12 盘教训） | 任何盘面、任何一级预算烧穿，输出必须是合法环：旧环复验合法（每格可铺 + 成环 + 围核心）则沿用，否则给"核心贴身环"。`rail(0)` 只允许出现在「镇中心 3×3 外圈本身不可铺」的退化盘上，且该退化须有回归用例钉死。现行"五级都失败 → 不设铁轨"的口径（规格 §2 兜底第 6 条）**废止** |
| R4 | **反缩水单调保险** | 上一帧的环仍合法、且对**当前基准集 B\*** 的覆盖数不比新解少 ⇒ 沿用旧环（v0.6.4 口径，比较基准随 O1 变更同步换 B\*） |
| R5 | **工程红线** | ① ES5、零依赖、无构建；② 求解器自包含于 Worker 三文件清单（`map.js + state.js + station.js`，blob 拼接，file:// 必然降级）；③ 输出接口不变：`railPath/railSet/railRect/railInner/contourB/railGrowHints/station` 7 字段 bit-exact 引用替换；④ 文件清单**四处耦合**（index.html / build_single.js / test_rail.js 沙箱 / solver-async.js srcs），新增文件必须四处同步——**v2 不新增文件**，重构在 state.js 内部进行 |
| R6 | **性能预算** | http 端（Worker 化）p50/p90 不劣于现行基线；单次求解最差链路总耗时不劣于现行各级墙钟之和（~1.25s 量级）；file:// 同步降级路径的最差感知不扩大（现状 ~1s）。实测基线锚点：随机盘均 12ms/P99 397ms；大轮廓盘均 40ms；怪兽盘 09:05 p50=853ms、09:12 p50=1005ms |
| R7 | **复用层不动** | solver-async 的盘面指纹守卫 / 分片合并 / 夜间落位闸 / newGame invalidate、STATION.solve 挂点、预览快速档（`railFast` 主解 90ms + 跳②⑤⑥⑦）、强制刷新（`forceRefresh`）语义全部照旧。v2 只替换 Worker 里跑的那个求解函数 |

## 7. 红线（证伪清单的 v2 继承口径）

**框架无关证伪——直接继承，v2 同样禁止**：
1. **先快后精两段换环**（10-09 大王否决）：玩家感知形状跳变；保持一次性换环。
2. **共享预算池 / 全局均摊**（v0.6.5 前科 + 10-09 再确认）：慢盘连坐。
3. **动字典序顺序或并列解取舍**：铁律，动则先拍板（档案 2.1 遗留风险原文）。
4. **承诺数学最优**：NP 级，预算内最好即为承诺上限。

**框架相关证伪——降级为先验，v2 下任何近似机制须重新 A/B 后才可采用**：
5. 扩搜索空间（HMAX 32/48 → 满覆盖反降 70%）——注意：该实验在**首命中 DFS + 旧框架**下测得，P3 的 U 全量方案属于此列，**必须**用 §8 语料重验。
6. 加预算 ×13（满覆盖仅 +6.4pp、耗时 ×3.8）。
7. min-cut / T-join 作整体求解器（目标函数不匹配）——作为构造子步骤使用不受此限，但需单独证明。
8. 2-core 必要条件预检（零误杀但判不死）。
9. "瓶颈=搜索能力"定性（09-28 证伪）：真瓶颈 = 往返自由度（mm=2 落地即证）。

## 8. 验收口径（A/B 判分依据）

### 8.1 回归套件处置（现 63 用例，全绿为基线）

- **口径不变、必须全绿**：合法性类（ringError 口径全部）、边界类（全空白/全废墟/走廊）、单调性/顺序生长、桥边约束 [14]、端头禁令 [46]、双十字重织 [47]、早停双闸 [48]、H 盲区行为锁 [60]。
- **期望重定标**（P2 过目后改期望值，方向应只变好）：[5] 细脖子（若 P1 允许纳入）、[13] 0721 支线（统一通道后数值）、[60]（若 P3 选 U 全量则整类盲区消失，用例转为"半岛纳入"断言）。
